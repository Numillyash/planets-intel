# Инструкции для AI-агентов: planets-intel

## Источник истины и порядок работы

- Общение с пользователем — **на русском**. Идентификаторы, команды, контракты API оставлять точными.
- В начале работы читать **`docs/CONTINUE_HERE.md`**, `docs/WORKFLOW.md`, `docs/architecture/ROADMAP.md`, актуальные исходники и релевантный `docs/handoff/`. Проверять *живые* GitHub `main`, PR, CI и `feature/operational-ui`; SHA в старом чате — исторический.
- Не создавать параллельный Dashboard / map / разведку, когда есть общий компонент и фактический слой. Проверять поведение на реальных разрешённых игровых данных; синтетический smoke — не production acceptance.
- Держать отдельно factual observation / историческую запись / inference / order draft / prediction и `known zero` / `unknown`.

## Правило сохранения контекста пользователя

**Перед каждым итоговым сообщением о существенном этапе** оставить в GitHub актуальный, целиком самостоятельный, **русскоязычный** промпт `docs/CONTINUE_HERE.md`. Не допускать ситуации, когда чат завершён, а продолжение существует только в переписке. Если работа включает несколько PR, каждый PR несёт свой промпт уже *до merge*. Обновляйте handoff после любых существенных изменений в рамках того же PR; не останавливайте работу ради отдельного «бумажного» PR после каждого коммита.

**Каждый PR без исключения** обязан менять в СВОЁМ diff:
1. `docs/CONTINUE_HERE.md` (полное самодостаточное продолжение, реальный номер текущего PR, факты/ограничения/следующие шаги).
2. `docs/PR_CHANGELOG.md` (запись с реальным номером PR и проверенным уровнем тестов).
3. Не менее одного дополнительного тематического документа (`docs/WORKFLOW.md`, `docs/architecture/ROADMAP.md`, `docs/handoff/*.md`, `README.md` и т. д.).

CI проверяет это через `tools/check_pr_handoff.py` на diff точных base/head SHA и проверяет актуальный номер PR. Нельзя выключать или обходить gate ради merge. Создавать PR достаточно рано, чтобы номер был реальным. Документация должна отличать проверенное от ожидаемого и не заявлять недоступный prod/Host результат.

## Инженерные границы

- Репозиторий **публичный**: не публиковать private RST, HAR, токены, ключи, cookies, заказы, личные сообщения, полные приватные скриншоты или содержательные приватные логи в issues/PR/artifacts.
- Приватные observer snapshots — только из выбранного собственного observer. Согласие в локальном приложении не расширяет разрешённую Planets.nu модель обмена; `INTEL_EXPANDED_SHARING_ENABLED` не включать.
- `planets-lab` — соседний исследовательский репозиторий; доказательства NuHost не объявлять причинно верифицированными по локальным симуляциям.
- Разработка в короткой ветке -> проверка -> PR -> handoff + changelog + docs -> CI точного HEAD -> merge -> post-merge CI. `feature/operational-ui` fast-forward **без force-push** после проверки истории; production `/opt/planets-intel/scripts/deploy/production.sh` выполняет оператор, CI сам по себе не означает deployed.
- Для длинных операций — существующие versioned scripts, безопасные минимальные команды, без секретов и без копирования больших логов в чат.
