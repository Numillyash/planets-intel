# Процесс разработки и сохранения контекста IntelBoard

Действует для `Numillyash/planets-intel`. Совместимая методика перенесена из `Numillyash/planets-lab` (`AGENTS.md`, `docs/WORKFLOW.md`, `tools/check_pr_handoff.py`), адаптирована к общей архитектуре IntelBoard и deployment-ветке.

## Обязательное продолжение в новом чате

Пользователь требует, чтобы **после каждого существенного ответа / выполненного этапа работы** в Git оставался актуальный готовый к вставке русскоязычный промпт. Канонический путь: **`docs/CONTINUE_HERE.md`**, всегда с актуальной задачей, ограничениями, тестами и следующими действиями. Перед финальным ответом убедиться, что он уже запушен; никогда не ограничиваться промптом в самом чате.

Для каждого PR до слияния: изменить `docs/CONTINUE_HERE.md` **целиком** (не сводку из старого контекста), `docs/PR_CHANGELOG.md` с текущим номером PR и минимум один содержательный документ по теме PR. Если в PR добавлены исправления после тестов, синхронизировать и документацию. Номер текущего PR получать из GitHub до добавления handoff, не угадывать.

Контракт для нового чата: переоткрыть `docs/CONTINUE_HERE.md`, живые refs GitHub, последние PR/CI, исходники и целевые тесты. Подготовленный SHA до PR не объявлять текущим после слияния.

## Проверка в CI

`.github/workflows/ci.yml` запускает `tools/check_pr_handoff.py` только для событий `pull_request` и сравнивает фактические base и head SHA. Скрипт проверяет обязательные файлы, тематическую документацию, самостоятельный достаточный промпт, реальный номер PR в handoff и changelog. Не ослаблять gate; исправлять содержимое текущего PR.

Пример локальной проверки, когда доступны оба SHA:

```bash
python tools/check_pr_handoff.py --base "$BASE_SHA" --head "$HEAD_SHA" --pr-number "$PR_NUMBER"
python -m unittest discover -s tools/tests -p 'test_*.py' -v
```

## Порядок инженерных действий

1. Проверить текущий `main`, `feature/operational-ui`, PR и CI. Изучить `docs/architecture/NEW_CHAT_START.md`, `docs/architecture/CURRENT_HANDOFF.md`, `docs/architecture/PROJECT_STATE.md`, `docs/architecture/ROADMAP.md`, релевантные файлы.
2. Изучить существующие общие компоненты, фактическую API-схему и тесты; не дублировать UI/слои.
3. Создать рабочую ветку от актуального `main`, сделать связанные изменения и регрессионные тесты, при необходимости получить Chromium screenshot из публичных источников.
4. Открыть PR для реального номера, обновить три категории документации в этом же PR, прогнать unit/browser/build/security checks и PR handoff gate на последнем head.
5. Проверить review threads/CI/mergeability, объединить, проверить `main` CI. Допускается объединить несколько этапов в одном пользовательском ответе, но не пропускать handoff.
6. Синхронизировать `feature/operational-ui` только через ff при подтверждённой истории; проверять её CI. Сервер деплоить отдельной штатной процедурой оператора и никогда не утверждать deployed по CI.

## Данные, безопасность и доказательства

- Держать `factual observation != history != inference != prediction != order draft`. `known zero != unknown`. Сохранять `game_id`, выбранного observer, `info_turn`, provenance.
- Публичные завершённые архивы не смешивать с private snapshots, их screenshot можно публиковать только после уверенности в публичности; приватные источники и cookies в публичный GitHub не загружать.
- Нет публично доказанного Host-соответствия без строгой независимой проверки; `planets-lab` — отдельное исследование.
- CI и Headless Chromium показывают сборку/тестовую сцену, **не доказывают**, что новая версия работает на production или что видимый marker соответствует реальному частному игровому наблюдению.
- Не добавлять запросов на extra private observers, не включать expanded sharing, не выполнять потенциально разрушающие серверные операции.

## Состояние Turn timing (PR #67)

Жёлтая линия на двух сглаженных графиках активности и до исправления соответствовала текущему **локальному времени браузера**, а не среднему/медиане. PR #67 добавил подпись `NOW`, общие LOCAL/UTC часы и единое обновление каждые 30 секунд, сохранив модель KDE и factual ticks. Кейс проверен синтетическим Chromium с замороженным временем, не в production. Источник подробностей: `docs/handoff/2026-10-24-turn-timing-now-visibility.md`. Новый чат должен проверять CI `main`, потом ff deployment-ветку, затем production только по процедуре оператора.

## Полезное из planets-lab, НЕ переносимое буквально

- Единый источник истины GitHub и CI-enforced PR continuation — применимы.
- Сокращённые versioned launchers, явные подтверждения evidence и один связный отчёт пользователю — применимы.
- Исследовательские `runtime-logs`, Host-causal gates, `public68` / heldout corpus и NuHost progression — **не импортировать** в IntelBoard UI как обязательные файлы или релизную метрику.
- Любое изменение security policy / consent — отдельный review boundary, не смешивать с фронтенд-правками.
