# Message reply + Intel surface merge — 2026-08-24

## User feedback addressed

1. `Reply` belongs to a concrete message, not a whole chat.
2. A standalone `Intel` surface with only Combat / Reports / Communications is unnecessary.

## Changes

- Added `CommunicationsDashboardPanel` as a normal Game Dashboard tab.
- Moved `Reply` from the conversation header to each factual player message.
- Reply composer shows the exact selected activity id, sender, turn and message preview.
- Reply recipient routing follows the selected factual conversation:
  - Public Board reply -> Public Board.
  - direct/group private reply -> the exact known recipient slot set.
- No unverified upstream parent id is sent. The current captured `/game/sendmessage` wire format proves destination/body but not a reply-parent parameter. Capturing one original-client REPLY request remains the blocker for true upstream threading.
- Removed the standalone Intelligence overlay and its top-level `Intel` navigation button.
- Canonical game surfaces are now only `starmap` and `dashboard`.
- Existing Dashboard tabs retain VCR and Reports; Communications is added beside them.
- Legacy URLs remain readable and are canonicalized without reload:
  - `view=intel&tab=combat` -> `view=dashboard&tab=vcr`
  - `view=intel&tab=reports|host` -> `view=dashboard&tab=reports`
  - `view=intel&tab=communications` -> `view=dashboard&tab=communications`
  - old `?intel=...` links follow the same mapping.
- Map VCR markers still open the modal VCR review directly.
- Map host-report selection now opens Dashboard -> Reports.

## Runtime validation

Run:

```bash
bash /opt/planets-intel/scripts/deploy/production.sh
```

Then verify:

1. Top game navigation is `Games · Dashboard · Starmap · TURN`, with no `Intel` button.
2. Dashboard tabs include `VCR`, `Reports`, and `Communications`.
3. Refresh on `?view=dashboard&tab=communications&chat=...` preserves Communications.
4. Old `?view=intel&tab=communications` canonicalizes to Dashboard Communications without a full page reload.
5. No chat-level Reply button exists.
6. Every Public Board/direct message has its own Reply action.
7. Clicking Reply opens the composer with a visible exact message target.
8. Replying in a direct group preselects the factual group recipient set.
9. Sending still uses the verified single-attempt message write path.

## Explicit remaining blocker

True Planets.nu upstream parent/thread creation is not claimed yet. Capture one Network request generated by the official client's per-message REPLY action before adding any `parent`/`parentid` field.
