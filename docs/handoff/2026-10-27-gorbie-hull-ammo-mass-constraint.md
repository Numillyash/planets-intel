# PR #71 — проверка корпуса Горби, боезапаса защитников и условной массы

## Ошибки, замеченные на скриншотах (27 октября 2026)

Пользователь показал Gorbie Class Battlecarrier (hull #70), наблюдаемая масса 2803 kt, пустой корпус 980 kt, бак 1760 kt. Threat Analysis ошибочно приписывал кораблю VCR #49 T18 с двумя торпедными аппаратами и выводил Mark 4 Photon как допустимого кандидата, хотя Горби имеет 0 аппаратов. Корабли собственной обороны Gemini/Virgo показывали `fighters ?` при наличии приватного поля `ammo`. В Intel рядом с наблюдаемым Warp 9 выводилось `Tech 9+` вместо конкретного двигателя. Пользователь предложил гипотезу полного бака: 2803 - 980 - 1760 = 63 kt.

## Реализация

- `backend/app/services/ship_threat_evidence.py`: чистые read-only функции квалификации VCR по hullid и слотовым пределам, точного определения `fighters`/торпед через тип корпуса и типизированная масса для гипотезы полного бака.
- `threat_analysis.py`: боевую запись допускаем только если совпадают идентификатор корабля, подтверждённый owner при наличии owner VCR, корпус и непротиворечивое вооружение. В частности, hull с нулём launchers никогда не получает кандидаты торпед, даже когда каталог торпед непустой. Вражеские нераскрытые боеприпасы не становятся known zero.
- Для собственного защитника отдельное поле `fighters` при наличии имеет приоритет, включая ноль. При его отсутствии `ammo` разрешено интерпретировать как истребители только если у известного корпуса есть bays, а торпедных аппаратов нет. Иначе значение остаётся unknown. Сообщаем `(private ammo)` и `info_turn` для устаревшего наблюдения.
- `loadout_inference.py`: аналогичная проверка VCR до привязки состава вооружения; при Unlimited Fuel и наблюдаемом Warp 9, если каталог оставляет ровно один движок с необходимым techlevel, он показывается как единственный **подтверждённый ограничениями каталога вариант**, а не безусловно точно наблюдаемый двигатель.
- `full_tank_scenario`: исходная масса, масса корпуса и ёмкость топливного бака дают **только условный** предел массы на остальные компоненты и возможные истребители; топливо непосредственно не раскрывается. При 2803/980/1760 остаётся не более 63 kt **на всё остальное вместе**, включая beam-оборудование и cargo. Следовательно, не более 63 истребителей *только в сценарии полного бака*, фактически может быть меньше. Для режима Unlimited Fuel полный бак не считается автоматически правдоподобным фактом.
- Вероятность победы не фабрикуется: без типа орудий/запаса истребителей противника точная величина требует отдельного запуска движка battle simulator с оговорёнными сценариями. В UI явно указан предел доказательности.

## Источники по игровым правилам

Официальная таблица `https://help.planets.nu/racesheet`: Gorbie hull #70, hull mass 980, fuel 1760, cargo 250, 10 beams, **0 torpedo tubes**, 10 fighter bays. Официальная документация `https://help.planets.nu/beginner-settings` описывает Unlimited Fuel как настройку новичковых партий, но не свидетельство реального заполнения бака. `https://help.planets.nu/cargo` подтверждает отдельные запасы fuel/torpedoes/fighters.

## Проверки и границы

`backend/tests/test_ship_threat_evidence.py` проверяет отвергание несовместимого VCR, чтение generic ammo на однозначном carrier, приоритет нулевого значения над ammo, отказ от выдуманных значений при неясном типе и расчёт условных 63 kt. Общий PR CI также проверяет Python/TypeScript и production image. GitHub CI и synthetic tests не являются доказательством private observer/runtime на сервере.

Секреты, личные RST и реальные закрытые данные не коммитятся. Factual наблюдения, inferred ограничения, условный сценарий и результат симуляции не смешиваются.
