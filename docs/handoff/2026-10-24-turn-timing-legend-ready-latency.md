# Turn timing — marker legend and misleading ready latency (PR #69, 2026-10-24)

## Обратная связь и проблема

Реальный скриншот Turn timing после PR #67 показывает некрасивую повторяющуюся надпись NOW над каждой жёлтой пунктирной линией, хотя общая легенда уже содержит текущие LOCAL/UTC часы. На каждой карточке также виден `This-game median ready after host 0m`, который при такой семантике вводит в заблуждение.

Исходники подтверждают: `backend/app/services/player_activity.py::_activity_times` вычисляет `ready_delays` как разность `turn_ready_at - host_completed_at`. При готовности игрока до завершения Host такая разность может быть **отрицательной**; исходная `formatDelay` в интерфейсе делала `Math.max(0, Math.round(minutes))`, скрывая отрицательную величину за нулём. До независимой проверки нельзя утверждать, что `0m` означает мгновенную готовность. Релевантные модели и API сохранены для последующего аудита.

## Изменение

- Оставлена единая общая легенда `NOW <time> local / <time> UTC` и цветовой образец; образец и все четыре вертикальные линии теперь сплошные.
- Удалена повторная SVG-текстовая подпись NOW, но сохранены доступное `aria-label` и `<title>` с тем же часовым контекстом. Общий `Date` и таймер в родительской панели не изменены.
- Удалена из **отображения**, но не из backend API, необоснованная медиана ready-after-host. Единственная видимая метрика внизу карточки — `Median first observed open after host (this game)`.
- Отрицательные, отсутствующие и нечисловые задержки отображаются `—`, а действительно неотрицательный `0m` остаётся разрешённым. Это защита представления, а не переписывание наблюдений.
- Уточнено, что first-open ограничено периодом polling, и исправлен отсутствовавший пробел в пояснении Running/Joining games.

## Проверки и границы

`frontend/scripts/turn-timing-now-smoke.mjs` теперь ожидает отсутствие плавающих NOW в четырёх SVG, solid stroke без dasharray, единый LOCAL/UTC timestamp, движение по таймеру, мобильную легенду, отсутствие ready-after-host UI и отсутствие ложного `0m` при отрицательном fixture. Выполняется из GitHub Actions `Public surface browser smoke` при PR.

Этот документ фиксирует **запланированный контракт реализации**; не считать CI зелёным до проверки последнего PR head и не считать test fixture private production acceptance. Вне scope: коррекция модели/семантики реальных host/ready timestamps, изменение private polling и числового KDE.
